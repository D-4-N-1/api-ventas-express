1. Introducción

Esta API permite que una aplicación cliente envíe datos de una venta al servidor. El backend recibe la solicitud mediante Express y ejecuta el procedimiento almacenado de MySQL db_registrar_ventas.

La operación visible en el código registra estos datos: id_producto, id_cliente, cantidad y fecha_venta. En el fragmento compartido, el servidor responde con HTTP 201 Created cuando la operación termina correctamente.

2. URL base

El servidor está configurado para escuchar en el puerto indicado por PORT, o en el puerto 3000 si no se define esa variable.

http://localhost:3000

En un entorno publicado, reemplaza localhost:3000 por el dominio y puerto del servidor.

Importante: confirma el prefijo antes de publicar esta documentación.
En la captura de server.js aparecen dos montajes de ventasRoutes con /api/v1/ventas, mientras que el registro de error del controlador menciona /api/v1/consolidado. Express combina el prefijo de app.use() con la ruta declarada en ventas.js. Por eso, la URL exacta debe comprobarse en ese archivo.

Con el montaje mostrado, si ventas.js declara router.post('/consolidado', ...), la ruta efectiva será:

POST http://localhost:3000/api/v1/ventas/consolidado

Si la URL que realmente deseas es /api/v1/consolidado, revisa el montaje del router para que coincida.

3. Formato de solicitudes

Envía el cuerpo de la petición como JSON y especifica la cabecera Content-Type: application/json.

CampoTipo recomendadoDescripciónRequerido
id_productoIntegerIdentificador del producto vendido.Sí*
id_clienteIntegerIdentificador del cliente que realiza la compra.Sí*
cantidadIntegerNúmero de unidades vendidas.Sí*
fecha_ventaString (fecha)Fecha de la venta; utiliza el formato que acepte tu base de datos, por ejemplo YYYY-MM-DD.Sí*

* El controlador mostrado comprueba que todos los campos estén presentes. Confirma en ventas.js las validaciones de tipos, rangos y formato de fecha.

4. Endpoint: registrar una venta

POST/api/v1/ventas/consolidado

Registra una venta ejecutando el procedimiento almacenado db_registrar_ventas. La ruta indicada aquí es la ruta efectiva si el router declara /consolidado y se mantiene el prefijo mostrado en server.js.

Cabeceras

Content-Type: application/json
Accept: application/json

Cuerpo de ejemplo

{
  "id_producto": 12,
  "id_cliente": 35,
  "cantidad": 2,
  "fecha_venta": "2026-10-23"
}

Respuesta de éxito — HTTP 201

{
  "status": "success",
  "message": "Venta registrada exitosamente",
  "datos_registrados": {
    "id_producto": 12,
    "id_cliente": 35,
    "cantidad": 2,
    "fecha_venta": "2026-10-23"
  }
}

El ejemplo refleja la estructura visible en el código; los valores son ilustrativos.

5. Respuestas y errores

201 · Created

Venta registrada

La operación se completó y la respuesta incluye los campos enviados.

400 · Bad Request (si así lo configura el controlador)

Datos obligatorios ausentes

El fragmento muestra el mensaje Todos los campos son obligatorios. Verifica en el bloque completo cuál código HTTP se utiliza para esta validación.

{
  "message": "Todos los campos son obligatorios"
}
500 · Internal Server Error

Error al registrar la venta

El código mostrado devuelve una respuesta de error cuando falla la operación con la base de datos.

{
  "error": "Internal Server Error",
  "message": "Error al registrar la venta en la base de datos"
}
Los códigos y cuerpos de error deben contrastarse con el controlador completo antes de considerar esta sección como contrato definitivo.

6. Ejemplos de consumo

cURL

curl -X POST "http://localhost:3000/api/v1/ventas/consolidado" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{
    "id_producto": 12,
    "id_cliente": 35,
    "cantidad": 2,
    "fecha_venta": "2026-10-23"
  }'

JavaScript con fetch

async function registrarVenta() {
  const respuesta = await fetch(
    "http://localhost:3000/api/v1/ventas/consolidado",
    {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        "Accept": "application/json"
      },
      body: JSON.stringify({
        id_producto: 12,
        id_cliente: 35,
        cantidad: 2,
        fecha_venta: "2026-10-23"
      })
    }
  );

  const resultado = await respuesta.json();

  if (!respuesta.ok) {
    throw new Error(resultado.message || "No se pudo registrar la venta");
  }

  return resultado;
}

registrarVenta()

7. Notas de integración y configuración

  • Envía siempre JSON válido y los cuatro campos requeridos.
  • Comprueba que los identificadores de producto y cliente existan en la base de datos.
  • Verifica el formato de fecha_venta y que cantidad sea un entero positivo, si esa es la regla de negocio.
  • No expongas las credenciales de MySQL del archivo .env al cliente. Solo el servidor debe acceder a ellas.
  • En server.js, coloca app.use(express.json()) antes de montar las rutas, para que Express pueda interpretar el cuerpo JSON antes de ejecutar el controlador.
  • La captura muestra el montaje de ventasRoutes repetido. Deja una sola declaración, salvo que exista una razón concreta para montarlo dos veces.
  • En producción, configura HTTPS, validación de entrada y una estrategia de autenticación/autorización si el servicio no debe ser público.
Antes de entregar al cliente: comprueba la ruta exacta en ventas.js, confirma el código HTTP de validación y prueba los ejemplos contra el servidor en ejecución.
